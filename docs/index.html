Self-hosted webhook deploy runner

Deploy on every push, from your own server.

webhookr is a self-hosted webhook runner. Point a GitHub (or generic) webhook at it. When the webhook fires, it does a git pull on the configured branch and runs your deploy command, logging everything so you can tail it later.

$ curl -fsSL https://github.com/kodin00/webhookr/releases/latest/download/install.sh | sh

Installs the Linux x86_64 binary to /usr/local/bin/webhookr, verifies its checksum, and sets up a webhookr systemd service that starts on boot and restarts on failure.

Features

Manage projects from a terminal UI, a CLI, or an optional browser dashboard.

  • Webhook-triggered deploys

    Each project maps a URL slug to a Git checkout plus a deployment preset or custom shell command. Deliveries are verified against a per-project secret.

  • Docker Compose presets

    Built-in compose_build, compose_pull and compose_up presets, or a custom shell command.

  • Automatic clone

    Give it a repository URL and it clones the branch for you. Private repositories work over HTTPS with an access token.

  • Rollback with database restore

    Every deploy records its commit. Redeploy any past successful run, restoring the database dump from just before it when the project has a database.

  • Multi-branch deploys

    Deploy several branches from one repository, each with its own preset, compose file, env file and database settings.

  • Live logs

    Run history and per-run logs stream to disk as commands produce them, so a long docker compose build can be followed while it runs.

  • TUI, CLI and web admin UI

    An interactive terminal UI, a scriptable CLI, and an optional server-rendered browser dashboard with no build step and no CDN.

  • GitHub commit status

    Optionally report each deploy as pending, success, failure or error on the commit, with a link to the run log.

  • Telegram notifications

    Post a message when a deploy starts, succeeds or fails, through a bot you own.

  • Cloudflare Tunnel

    Publish the webhook endpoint and admin UI on a real HTTPS hostname without opening ports.

  • Branch-aware triggers

    Deploy on pushes, PR merges, or both. A push to another branch does not trigger a redundant deploy.

  • One run at a time

    A trigger that arrives while a project is deploying is refused rather than queued, so two pushes cannot race git pull.

How it works

  1. A webhook arrives. GitHub sends a delivery to /hooks/<id>. webhookr checks the X-Hub-Signature-256 header against the project's secret before running anything. Non-GitHub senders can use token mode instead.
  2. Source is updated. git fetch, checkout and pull run on the configured branch. If the checkout does not exist yet, it is cloned from the repository URL.
  3. Your deploy runs. The Compose preset or custom command runs from the project directory. The run, its trigger, and its log are recorded.
  4. You see the result. Follow the log in the TUI, CLI or web UI, and optionally get a GitHub commit status or Telegram message.

Quick start

After installing, register a project and start the daemon.

# 1. Register a project (prompts for anything you don't pass)
webhookr add \
  --name "My Site" \
  --path /srv/my-site \
  --repository https://github.com/me/my-site.git \
  --branch main \
  --preset compose_build \
  --compose-file compose.production.yaml

# 2. Get the secret + webhook URL (printed on add, or via:)
webhookr key --id my-site

# 3. Start the daemon (systemd recommended for production)
webhookr serve
# ...or launch the interactive TUI
webhookr

Then add the webhook in your GitHub repository under Settings → Webhooks. The full steps are in GitHub webhook setup.
